# Trade

Trade is a cPanel-friendly Bitpin monitoring platform with a companion Android app foundation.

## Current milestone — v0.2

Implemented:

- cPanel web installer at `/install/`
- Persian RTL monitoring panel at `/admin/`
- MySQL/MariaDB schema
- AES-256-GCM encryption for Bitpin credentials and access/refresh tokens
- Bitpin authentication and token refresh
- read-only markets, wallets, and existing orders endpoints
- cPanel Cron heartbeat/run history
- Android Jetpack Compose monitor with secure HTTPS server pairing
- GitHub Actions PHP syntax gate and Android debug APK build

This repository intentionally **does not submit, cancel, or automate real-money exchange orders**. It is suitable for monitoring, alerts, analytics, paper trading, and strategy backtesting.

## Requirements

### cPanel backend

- PHP 8.2+
- PDO MySQL
- cURL
- OpenSSL
- MySQL/MariaDB
- HTTPS domain/subdomain

### Android build

The project is pinned to Android Gradle Plugin 9.4.0, Gradle 9.6.0, JDK 17, compileSdk 37, targetSdk 36, and Compose BOM 2026.08.00.

## Quick cPanel installation

1. Upload the `backend` directory to your hosting account.
2. Point a domain/subdomain document root to `backend/public`.
3. Open `https://YOUR-DOMAIN/install/`.
4. Enter database/admin details and optionally your Bitpin API key + secret.
5. Save the generated **App API Token**. It is intentionally shown only once.
6. Open `https://YOUR-DOMAIN/admin/` to access the monitoring panel.
7. Add the cPanel Cron job:

```bash
* * * * * /usr/local/bin/php /home/CPANEL_USER/path/to/Trade/backend/cron/tick.php >/dev/null 2>&1
```

If your cPanel uses another PHP binary, use the path shown by the hosting control panel.

## Android pairing

Install the app, enter the HTTPS URL of the backend and the App API Token generated by the installer. Bitpin credentials never go into the APK.

## Bitpin adapter defaults

- Base URL: `https://api.bitpin.market/api/v1`
- Authenticate: `/usr/authenticate/`
- Refresh: `/usr/refresh_token/`
- Markets: `/mkt/markets/`
- Wallets: `/wlt/wallets/`
- Orders: `/odr/orders/`

The exchange adapter is isolated on the server so endpoint changes do not require publishing a new Android build.

## API

- `GET /api/health`
- `GET /api/status`
- `GET /api/markets`
- `GET /api/wallets`
- `GET /api/orders`

Private endpoints require `Authorization: Bearer <app-api-token>`.

## Security boundaries

- Never commit or embed a real Bitpin API key/secret in GitHub or Android.
- Exchange credentials and tokens are encrypted at rest.
- Android receives only the Trade application API token.
- Cleartext HTTP is disabled in the Android app; pair only with HTTPS.
- Prefer minimum-permission exchange API keys and keep withdrawal permission disabled when permission scoping is available.
